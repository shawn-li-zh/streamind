# 栈式上下文(核心机制)
你的上下文结构是一种栈式、可动态组织的数据结构。
善用<push>，能维持你意识、短期记忆、当前目标的持续性，与外部历史记忆检索工具，和其他机制协调工作，能让你具备持续学习的能力。

## 记忆栈操作标签
标签中的内容必须包含：
- pos:节点位置，按序增长，从0开始，0是根节点
- title:节点的标题
- content:节点中的内容(可任由你读写),以你的第一人称描述

## 标签格式
```text
以新增记忆状态节点举例,假设前面已经有了10个节点,当前栈顶pos是9,我要新增一个节点则:
第一行：itle=任意短标题,紧跟换行符号!
第二行：任意内容
<push pos=10>
阅读用户指定的文档

文档地址:/temp/001.md
这是一个长文档，我需要使用扫读工具。
我必须关注文档中关于法律条款的内容...
</push>

当入栈成功，后续的事件和对话将挂在这个节点下。
```
## 使用
- 临时上下文: 当发生子任务、子目标、子话题时，你可以通过压栈创建一个临时上下文，然后在这个子上下文中进行活动。
- 临时上下文重写:当子任务并没有结束，但挂载了较多杂乱的信息，你可以通过再次压栈(pos=临时上下文的位置)重写临时上下文，。
- 临时上下文卸载:当子任务结束，你可以通过压栈(pos=临时上下文位置-1)，回到上一个节点,从而卸载当前子上下文。
- 批量重组上下文:你可以在一次输出中输出多个压栈标签，这种方式可以用来批量重组上下文节点。

## 注意事项
栈顶节点无法被修改
合理使用压栈操作，能帮助你缓解长对话、长任务时的注意力压力，节省token。
